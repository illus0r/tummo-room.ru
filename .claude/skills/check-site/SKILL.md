# Проверка сайта tummo-room.ru

Быстрый смоук-тест после правок в шаблонах `.njk`: собрать сайт, открыть каждую
страницу в headless-браузере и убедиться, что ничего не сломалось.

## Когда использовать

- Пользователь просит проверить/протестировать сайт, прогнать тесты, сделать QA.
- Только что отредактирован любой `src/*.njk` или что-то в `src/assets/`.
- Речь о битых ссылках, битых картинках, горизонтальном скролле, вылезающей
  вёрстке или ошибках в консоли.
- Перед тем как посоветовать задеплоить/запушить изменения — стоит прогнать
  разок для очистки совести.

## Как запустить

```bash
pnpm run check-site
```

Первый раз — поставь зависимость (headless-браузер уже стоит на машине, это
только сам драйвер):

```bash
pnpm install
```

Скрипт сам:
1. собирает сайт (`pnpm run build`);
2. поднимает статический сервер поверх `_site/` на свободном порту;
3. находит **все** собранные `.html`-страницы (не только `index/ceramics/workshops` —
   любую новую страницу тоже подхватит);
4. открывает каждую в headless Chrome и проверяет.

Полезные флаги:

- `node .claude/skills/check-site/scripts/check-site.js --skip-build` — не
  пересобирать, взять уже готовый `_site/` (быстрее при повторных прогонах).
- `--widths=375,768,1280` — свои ширины для проверки скролла.
- `--json=report.json` — дополнительно сохранить отчёт в JSON.

(Через `pnpm run check-site -- --skip-build` тоже работает — `--` передаёт флаги
дальше в скрипт.)

## Что именно проверяется

Для каждой страницы:

| Проверка | Как |
|---|---|
| **Сборка/ответ** | `pnpm run build` не упал, страница отдаёт `200` |
| **Внутренние ссылки** | все `<a href>`, ведущие на этот же сайт (не `http(s)://чужой-домен`, не `mailto:`/`tel:`), реально существуют — без 404. Внешние ссылки (ВК, чайные магазины и т.п.) сознательно **не** проверяются — сеть недоступна/нестабильна не по вине сайта |
| **Картинки** | каждый `<img>` реально загрузился (`naturalWidth > 0`), а не показывает alt вместо кадра |
| **Горизонтальный скролл** | `document.documentElement.scrollWidth` не больше `clientWidth` на 375px (мобила) и 1280px (десктоп) |
| **Консоль браузера** | ноль `console.error` и необработанных JS-ошибок |

Упавшие сетевые запросы (например, недоступны Google Fonts на этой машине)
выводятся отдельным списком «предупреждений» и **не** считаются провалом — это
шум окружения, а не баг сайта.

## Как читать отчёт

```
/ceramics/
  сборка/HTTP:  ✓ 200
  ссылки:       ✓ 3 проверено, 0 битых
  картинки:     ✗ 27 проверено, 1 битых
      ✗ /assets/img/photo-hand.webp
  скролл вбок:  375px ✓ · 1280px ✓
  консоль:      ✓ 0 ошибок
```

Каждая строка независима — если сломалась только одна проверка, остальные всё
равно покажут ✓. Код выхода `0`, если всё чисто, `1` — если хоть одна проверка
хоть на одной странице провалилась (удобно вешать на CI/pre-commit).

Генеративные страницы (например `/ceramics/` с плавающими фото и «этажами») сами
крутят таймеры бесконечно — это нормально, скрипт просто закрывает вкладку
после проверки и не ждёт, пока они «закончатся».

## Если Chrome не находится

Скрипт ищет установленный Google Chrome/Chromium по стандартным путям (mac,
Linux, Windows). Если у тебя нестандартная установка — укажи путь явно:

```bash
CHROME_PATH="/путь/к/Chrome" pnpm run check-site
```

## Устройство скрипта

Один файл: `scripts/check-site.js`, только `puppeteer-core` (без своей
Chromium — использует уже установленный в системе браузер, никаких лишних
сотен мегабайт) плюс встроенные модули Node. Раздельные функции:
`findHtmlRoutes` (обход `_site/`), `startServer` (мини-статик-сервер с
поведением как у GitHub Pages — `/foo/` → `foo/index.html`), проверка ссылок
через обычные HTTP-запросы к этому серверу, остальное — через
`page.evaluate` в браузере. Если понадобится добавить проверку (например,
`<link rel="canonical">` или веса страниц) — правь прямо в этом файле, он
короткий и плоский, отдельного «фреймворка» тут нет.
